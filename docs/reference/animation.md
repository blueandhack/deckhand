Spec: `docs/superpowers/specs/2026-10-05-board2-anim-core-tap-feedback-design.md`.
Plan: `docs/superpowers/plans/2026-10-05-board2-anim-core-tap-feedback.md`.
This is piece 1 of 3. Transitions (piece 2) and list fling/bounce (piece 3) are not built yet.

## The rule everything rests on: the tint is never in the framebuffer

`PanelShim::setOverlay()` stores ONE rounded rect, tint and alpha. `flush()` blends it into
the pixels it gathers for the panel, and `readRect()` blends it into what `SCREENSHOT` reads.

The framebuffer underneath keeps true content. A redraw under a lit control (the 1s tick, a
payload) is correct the moment it is flushed, and clearing the layer can never paint a stale
image back.

The first design drew the tint into the framebuffer over a snapshot and cancelled the
animation on a foreign draw. That cannot be made right when a draw covers only PART of the
rect (spec, Revision 1).

`anim-check.mjs` fails by name if `anim.ino` calls a drawing primitive.

`PanelShim::watch()` has one job: to tell `pressAfterDispatch()` whether the action
repainted the control it fired from. If it did, the layer is dropped at once; a tint fading
over a different screen would be a ghost. If it did not, the 120ms release flash runs.

## Timings and curves

| | value | where |
|---|---|---|
| frame | 16ms, only while a tween runs | `ANIM_FRAME_MS`, `anim.ino` |
| press in | 0 -> 51 (20% toward `COLOR_ACCENT`) over 40ms, ease-out cubic | `PRESS_IN_MS`, `PRESS_ALPHA` |
| release / slide-off / drop | -> 0 over 120ms | `PRESS_OUT_MS` |
| slop | 12px outside the lit rect | `PRESS_SLOP_PX` |

The easing tables (33 entries, 0..1024) were generated by:

    node -e 'const back=(t,c)=>1+(c+1)*Math.pow(t-1,3)+c*Math.pow(t-1,2);
    for(let i=0;i<=32;i++){const t=i/32;console.log(Math.round(1024*(1-Math.pow(1-t,3))),
    Math.round(1024*back(t,1.5)))}'

`c = 1.5` is the value that makes the back curve peak at exactly 1.08 (1106 in the table).
Piece 1 uses only the cubic. The back curve is for arrivals in pieces 2 and 3, and is
declared now so the checker binds its shape.

## When a tap acts

**Board 2 acts on the LIFT**, at the press point.

These still act on the press:
- wake and undim
- the octopus and the emoji grid ("any tap dismisses")
- the compose processing bar
- the keyboard's key band, with its own arm-then-commit
- the three blocking drag lists (`tapBlocksUntilLift()`, whose halves live beside each
  handler)

The tap chain itself is `dispatchTap()`, moved verbatim out of `handleTouch()`.

`pressLift()` DROPS a tap if the surface signature (`pressSurfaceSig()`) or the control under
the press point changed while the finger was held. The control check compares the rect AND
an identity key: the session/project id hash in `r[5]`. A dropped tap logs `PRESS: dropped`.
A row's rect can survive a re-rank while the session in it does not, which is why the key
exists.

**Board 1 still acts on the press.** Its handler compiles to the same code: `dispatchTap()`
is inlined back into `handleTouch()`, and one `bne` re-encodes with its operands swapped.

## What lights (piece 1)

- tab cells
- session rows (never the scroll rail)
- PROJECTS rows on both levels (not the honesty row)
- SETTINGS HOME rows and the confirm dialog's YES/NO
- answerable ask options
- the reply panel's action buttons (the DRAWN button, `UI_ACT_GAP` narrower than its tested
  column)

NOT lit yet: settings steppers, toggles and segments; the settings back band; the detail
header chips; the ask SPEAK/REPLY row; the compose reply bands and chips; the scrollback
header; the USAGE cards. Taps on these still act on the lift.

## Instruments

- `PRESSTEST <x> <y>` / `PRESSTEST off`: lights the layer at a point and holds it, so
  `SCREENSHOT` can check the rect. It never dispatches. See CLAUDE.md's command table.
- `PERF anim`: frames, flush avg/worst, tweens, slide-offs, drops. A frame IS a flush of the
  lit rect, with no compose.
