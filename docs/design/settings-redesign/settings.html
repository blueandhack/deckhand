Settings, redesigned

Board 2, 320×480. Every glyph below is the real Spleen bitmap read out of Spleen8x16.h and Spleen12x24.h; every position is a constant parsed from board_es3c35p.h. No Mac font is used anywhere — the last mockup that reached for Menlo flattered the design by about 30% more ink than the device can put on the glass.

The design — A + B, all six screens

HOME plus five groups. The pager band becomes a back band of exactly the same height, so every group keeps PAGE_TOP 104 and the existing page code drops in under it. Each HOME row carries its group's current value, so the common question — what brightness, how many Macs, is the host talking to me — is answered with no tap at all.

Every page now lands between 16 and 48px of slack, against 10–121 today. Measured by the headless checker that renders all ten screens:

Actions is the loosest at 48 and that is honest rather than padded — it holds three buttons, so they are drawn at 56px instead of 50 and given room to separate.
SOUND is a real group, not a leftover. It carries output and input, because a mic test is a sound test — and it is the one action you run repeatedly, since MIC_GAIN is settled by watching MICMON while speaking rather than computed. Moving MIC TEST here is what takes ACTIONS down to three, so ACTIONS becomes purely things that change or end state.
  • TEST BEEP earns its place: the ES8311's volume scale is linear in dB, so LOW/MED/HIGH are {55, 70, 85} out of 100 and roughly 13dB apart, with everything under ~40 inaudible on this hardware. A word cannot tell you what a volume sounds like — the same reason the menu bar's sound picker plays on select, and the reason TONELADDER exists at all.
  • No bar under VOLUME, deliberately. board_es3c35p.h records that only BRIGHTNESS gets one, being the single continuous 0–100 setting; three named presets with a bar under them would be decoration. I kept that decision rather than quietly overriding it.
  • The line under the toggle says what actually beeps — a needs-input transition, which is the beeper's only job. 32 characters at 8px is 256px centred on 320.
DISPLAY did not just lose VOLUME — it spent the 92px. My first pass moved volume out and left the page with 127px of dead space, which is the exact defect this redesign exists to fix. So THEME stops being a cramped third-width cycle button and becomes a 3-segment selector that shows all three options at once. It was never a uiToggle anyway — it has three states, and a cycle button shows one while hiding the other two.

And AUTO finally says what it means: AUTO = light 07:00 to 19:00. AUTO is a clock, not a sensor — every ADC1 channel on this board is spoken for (touch, battery, mic) and ADC2 is unusable while BT is up, so there is no light to measure and never will be. Labelling it AUTO with nothing beside it implies hardware that does not exist, which is the same rule that stops the farewell screen promising a touch wake this board cannot do.
What else moved, and why.
  • STATUS leads with the two facts you came for — is the host talking to me, and how is the battery — each a 12x24 line with its detail dimmed underneath. The eight diagnostic values collapse into one two-column card instead of eight full-width rows.
  • The live Mac rows move to PAIRING. Today they are on page 0 and page 3. Consolidating frees two rows on the busiest page and gives the pairing list the one thing it lacked: whether each remembered Mac is connected right now.
  • ACTIONS gets captions and a severity spine. The two destructive buttons sit under CANNOT BE UNDONE and carry a solid 4px bar — the same visual language the session rows already use — so severity survives greyscale and colour-blindness.

Two real defects found while measuring this, neither cosmetic.

1. board_es3c35p.h:1689 describes a page that no longer compiles. Its comment opens "THREE buttons, not four: BOARD_HAS_MIC is 0 here" — but line 18 of that same header is #define BOARD_HAS_MIC 1, set when the ES8311 capture path landed. So ACTIONS really has four buttons today, and the comment's arithmetic goes with it: it puts the hint at y=302 with 148px clear, where the real values are 364 and 86px. It even scolds an earlier revision for copying board 1's four-button chain, and is now wrong in the opposite direction. Prose is not parsed, so no checker caught it.

2. CLAUDE.md still calls MIC TEST an "open inconsistency" that "reaches micMonitor()'s stub" and paints nothing. That was true before the capture path existed; the same file now documents that path as measured and working. The button is fine — the note about it is stale.
Severity on the ACTIONS page is carried by outline hue alone. uiButton's signature is (..., uint16_t tint = COLOR_ACCENT, bool filled = false, ...) and page 2's four calls all omit filled — so MIC TEST, CALIBRATE TOUCH, RESET PAIRING and POWER OFF are four identically shaped outlined slabs differing only in stroke colour. That is the one thing this repo's own rule forbids: status is never carried by colour alone, which is why session state gets a filled circle / filled square / hollow ring and the palette is checked for greyscale separability. The buttons never got that treatment.

The geometry is arithmetic from the header and the type is the real bitmap, but three things need checking before any of it is built: the repaint cost of a HOME→group transition (a full flush is ~30ms on this board, the same as today's page switch — no regression, but not free); whether drawSettingsStatic()'s cache-reset discipline extends cleanly to a screen enum rather than a page index; and the RAM for HOME's summary strings, which should be zero if they are composed into an existing scratch buffer rather than stored. The severity spine and HOME's 70px pitch also need settings-geom-check.mjs assertions, or they are constants no checker parses — which is exactly how the stale comment above happened.
