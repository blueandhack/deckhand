**Third alpha of Deckhand.app.** Installed 0.1.x copies update to this automatically (Sparkle); new installs download the DMG below.

**Requires:** Apple Silicon, macOS 14 or later, and a Deckhand display (firmware is flashed from the repo with `./flash.sh`).

### What's fixed

- **"Open Deckhand at login" now sticks.** After a restart the background host came back but the menu-bar icon did not, because the app's login item was switched off. Two causes are fixed:
  - The switch in Settings › General snapped back for up to 15 seconds after you flipped it, so it looked like the click had not worked. It now shows the real state straight away.
  - The first-run setup could finish without making Deckhand a login item, when the background host was already set up from an earlier install. Setup now turns it on as it finishes. It does this on the first run only, so switching it off later is respected.

  **If you are updating:** check Settings › General › *Open Deckhand at login* once. If it is off, switch it on. The update does not change that setting for you.

### Install (new users)

1. Download `Deckhand-0.1.2.dmg`, open it, and drag **Deckhand** onto **Applications**.
2. Open it from Applications and follow the setup window (it asks before touching Claude Code's settings and backs up first).
3. Restart Claude Code so it picks up the hooks.

### Still not verified

A Mac with no Node or Homebrew installed; a notched MacBook screen's menu bar; a first-time Bluetooth prompt from a fresh permission state; **Uninstall**; Gemini usage, which reads an undocumented local interface of the Gemini app; and the setup fix itself, which only runs on a first install.
